## Reader-semantics audit

The cpio reader records hardlink identity only when `archive_entry_nlink(entry) > 1`. Therefore, overlap between a preserved single-link inode value and the synthetic high-value range does not by itself create a false extracted hardlink.

The actual uncovered edge is inode zero with hardlink cardinality:

```text
source inode = 0
nlink         >= 2
```

The current mapper returns archive inode zero before entering its hardlink-identity lookup/allocation path. Distinct zero-inode hardlink groups on one device can therefore still share the same serialized identity, while repeated members cannot be distinguished by source tuple.

## Next discriminator

Add a deterministic native regression with:

1. zero-inode hardlink group A, two entries, one device;
2. zero-inode hardlink group B, two entries, a distinct source identity boundary;
3. repeated members of each group must reuse their own synthetic value;
4. groups A and B must serialize different nonzero inode fields;
5. `TRAILER!!!` and ordinary unnumbered single-link entries must remain zero.

The likely implementation rule is:

```text
preserve inode zero only when nlink < 2;
route inode zero with nlink >= 2 through hardlink synthesis.
```

Negative source inode handling should be reviewed in the same focused change; the current warning path reports positive overflow only.
