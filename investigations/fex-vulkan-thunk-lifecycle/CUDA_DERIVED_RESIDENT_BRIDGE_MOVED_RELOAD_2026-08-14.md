## Deferred-callback fixture

A synthetic native ARM64 `libcuda.so.1` models the relevant real CUDA graph lifetime shape:

1. `cuGraphAddHostNode` receives the converted `CUDA_HOST_NODE_PARAMS` and **retains** `fn` plus `userData` without invoking the callback;
2. the guest closes generation 1 of `libcuda.so.1`;
3. the probe proves generation-1 wrapper mappings disappear;
4. all former wrapper ranges are reserved with `MAP_FIXED_NOREPLACE`;
5. generation 2 reloads at different addresses;
6. generation 2 does **not** call `cuGraphAddHostNode` again;
7. only then `cuGraphLaunch` asks the synthetic host library to invoke the callback retained from generation 1.

The native ARM deferred control succeeds and invokes the callback exactly once.

## Interpretation

This is the strongest cross-library evidence so far for the per-library resident bridge architecture.

The callback ABI conversion itself is generated by the `callback_member` prototype. The only difference relevant to the lifetime A/B is ownership of FEX's fixed guest callback unpacker/signature bridge:

- wrapper-local unpacker generation becomes unmapped and the retained host trampoline faults after moved reload;
- process-resident per-library unpacker remains executable and the retained callback succeeds after the ordinary wrapper is gone.

The result is independent of Vulkan and DRM and covers a much larger generated CUDA signature surface (`364` unique signatures).

It also sharpens the concurrency/lifetime model: an already-selected or host-retained **resident** FEX bridge does not need to be revoked merely because the ordinary API wrapper unmaps. Descriptor revocation plus active execution drain is still required when the escaped bridge executable itself must be reclaimable, or when an arbitrary guest target behind the bridge can disappear independently.

## Real NVIDIA follow-up

This GPU-free test deliberately isolates FEX thunk architecture. A real NVIDIA-driver test remains useful as a fidelity check because CUDA graph host nodes execute their host callback when the graph node runs, rather than necessarily during node creation.

The next real-driver discriminator should use a real CUDA graph create/add-host-node/instantiate/launch sequence and verify that the callback is deferred until graph execution. If wrapper lifetime can be manipulated safely in that environment, it can additionally test whether the real driver retains the FEX-created callback trampoline across the same logical boundary.

That real-driver test is confirmatory; it is not required for the causal resident-sidecar result above.

This is fork-local research evidence, not upstream-ready FEX contribution code.
