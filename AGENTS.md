# Agent router

This is a `teamleaderleo` owned research fork. For internal work in owned repositories and forks, broad reversible research is already authorized: inspect, edit, test, commit, push owned branches, and use disposable owned-repository CI/workflows when useful. Internal experiment history may be messy; optimize for evidence rather than upstream-ready presentation.

## Always preserve

- Third-party/upstream interaction is a separate authority boundary. Do not comment, review, react, open issues/PRs, dispatch upstream workflows, or create accidental backlinks without explicit authorization.
- When owned-fork text must mention a third-party GitHub issue, pull request, or commit before that upstream interaction is authorized, use the repository's redirect-link convention so the reference does not create a backlink/timeline effect; load `AGENT_PLAYBOOK.md` if the boundary is unclear.
- `upstream greenlight` authorizes only the reasonably clear upstream repository and interaction in context. It does not imply merge, release, deployment, credentials, spending, private-data access, or unrelated authority.
- Do not represent owned-fork research as upstream-authored or upstream-ready.
- Never invent contributor identity, email, DCO/sign-off, credentials, or a noreply address.
- Prefer ordinary local Git/repository work over elaborate automation when it answers the question. Disposable owned-repository Actions are an experimental harness, not a required transport.

## Route before reading

Do not automatically read every project manual.

- product/orientation -> `README.md` or `START_HERE.md` when needed;
- research procedure/evidence -> `FIELD_GUIDE.md`;
- genuinely coupled multi-lane work -> `ADAPTIVE_COORDINATION.md`;
- upstream candidate/history/sign-off -> `SOURCE_BRANCH_HYGIENE.md` **only after** the human designates an upstream candidate;
- complete owned-fork/upstream policy rationale -> `AGENT_PLAYBOOK.md` when a boundary question needs it.

A human-designated upstream candidate must load `SOURCE_BRANCH_HYGIENE.md` before changing candidate history or preparing submission. Temporary internal machinery must not leak into candidate history.

## Finish

Use repository-owned checks appropriate to the task. Keep external-action authority explicit and preserve useful experiment receipts. A later human instruction may narrow or revoke the standing internal authority.
